\chapter{Implementation}

\section{Configuration and Data Contracts}
\label{sec:impl-config}

Every experiment in this study is a point in a multi-dimensional space:
hardware tier $\times$ model $\times$ retrieval policy $\times$ dataset.
Hard-coding combinations would produce a combinatorial explosion of
near-duplicate scripts and fragile reproducibility claims. Configuration is
instead expressed as YAML files \emph{deep-merged} in increasing precedence,
\[
  \texttt{base} \rightarrow \texttt{hardware} \rightarrow \texttt{model}
  \rightarrow \texttt{policy} \rightarrow \texttt{experiment},
\]
so a later file overrides only the keys it names. The merged dictionary is
validated into a typed \texttt{ProjectConfig} (Pydantic) \emph{before} any
expensive computation, a property that matters when a single run occupies
hours of CPU time.

The \texttt{logits\_all} flag is the worked example of a design decision
encoded declaratively. The entropy and margin gates need the model's
per-token logit distribution, which the inference library retains only when
constructed with \texttt{logits\_all=true}, at a memory cost of roughly
256\,MB. The low hardware tier (4\,GB) overrides the flag to \texttt{false},
which automatically renders those gates unavailable and forces the ensemble
into its probe-only degraded mode (Section~\ref{sec:method-ensemble}). The
hardware trade-off is thereby auditable from configuration alone, with no
runtime conditional to discover in code.

All inter-layer communication passes through three dataclasses isolated in a
dependency-free schema module. \texttt{UnifiedQuestion} normalises any source
dataset into one shape (multiple-choice questions carry a \texttt{choices}
mapping and a gold letter; open-ended questions carry a gold answer string;
every question carries a tagger-assigned \texttt{risk\_level}).
\texttt{PolicyResult} is one policy's output on one question: answer text,
gate decision and signals, retrieved chunks, and profiling fields.
\texttt{RunRecord} adds ground-truth scoring and experiment metadata and is
serialised as one self-describing JSON Lines record per query.

The append-only JSONL audit log is central to both resumability and analysis.
Because each line is independent, an interrupted run resumes by reading back
the \texttt{question\_id}s already present and skipping them, which is essential
when full experiments run for hours on a laptop that may sleep or be
interrupted. A free-form \texttt{qvault} dictionary inside each record
carries gate-specific payloads (per-token entropy arrays, both probe drafts,
per-member votes, retrieved chunk texts) without schema changes, which is
what later allowed every analysis in Chapter~\ref{ch:eval}, including
calibration sweeps, ablations and paired studies, to run offline from logs
alone.

The clinical-risk tagger assigns each question a level in
$\{\text{low}, \text{medium}, \text{high}\}$ using a transparent,
training-free keyword rule set with precedence
$\textsc{high} \succ \textsc{low} \succ \textsc{medium}$ and a conservative
default of \textsc{medium}; high-risk cues include dosing, overdose, drug
interactions, contraindications and acute emergencies. A rule set was chosen
over a learned classifier deliberately: in a safety context the basis of each
risk label must be inspectable, and no labelled training data exists for the
task. The tagger's recall gaps on implicitly high-risk questions are
acknowledged as a limitation (Section~\ref{sec:disc-limitations}) and are one
reason the high-risk stratum is small.

\section{Model Backend and Prompting}
\label{sec:impl-backend}

The language model is served entirely on CPU by a backend wrapping
\texttt{llama.cpp} \citep{llamacpp}: Llama-3.2-3B-Instruct
\citep{llama3}, 4-bit quantised (Q4\_K\_M, GGUF). Determinism is enforced by
greedy decoding (temperature 0) and a fixed seed; the configuration validator
warns if a non-zero temperature is ever supplied, since it would silently
break reproducibility. Determinism was later verified end-to-end: replaying
logged questions reproduced the logged answers exactly
(Section~\ref{sec:eval-ablation}).

Two backend methods exist solely to serve the gates. \texttt{draft()} returns
generated text \emph{and} the raw logit array of shape
$[n_{\text{gen}} \times |V|]$, which is the entropy gate's input.
\texttt{get\_top2\_logprobs()} returns per-position top-two
log-probabilities via the completion API rather than the logit buffer, so it
survives \texttt{logits\_all=false}. Both are declared on the abstract
backend interface, which lets a \texttt{MockLLMBackend} supply deterministic
text and synthetic logit arrays, forming the foundation of the model-free test
suite.

Prompt construction separates message \emph{bodies} from the chat-template
\emph{wrapper}. A single \texttt{set\_chat\_format()} call at backend
construction selects the wrapper (\texttt{llama}, \texttt{qwen} or
\texttt{plain}), so no policy or gate can ever assemble a prompt in the wrong
format for the loaded model. The refactor that introduced this abstraction
could have silently invalidated every existing result; it was therefore
verified to produce byte-identical prompts for all eight prompt types under
the default Llama format before merging, which is precisely why the existing
Llama-3.2-3B logs remain valid. This is the mechanism through which the
scaling study (Chapter~\ref{ch:scaling}) ran without touching policy or
gate code: the Qwen2.5-7B and 14B experiments changed only the model file,
the chat format and the gate thresholds, executing the identical pipeline
on a hosted T4 GPU from a resumable notebook, with a four-check smoke test
gating each long run.

\section{Building the Medical Corpus}
\label{sec:impl-corpus}

The evaluation initially used a 200-chunk pilot corpus, which produced the
corpus-bottleneck finding of Section~\ref{sec:eval-corpus} and forced a real
corpus build. Verifying dataset paths \emph{before} committing to them, a
habit acquired when the originally planned open-ended dataset proved
unreachable at its published location, revealed that the StatPearls
sub-corpus was empty on the hosting hub, while the MedRAG textbooks
($\sim$126K snippets) and PubMed corpora resolved correctly. The corpus was
therefore assembled from the medical textbooks plus a 300,000-snippet PubMed
slice: \textbf{425,847 chunks}, roughly $2{,}100\times$ the pilot.

Indexing 426K chunks on a memory-constrained CPU laptop required a build that
survives interruption. The build script embeds chunks in fixed shards of
2,000, checkpointing each shard to disk, so a crash or process kill loses at
most one shard of work. Shards are then assembled into an exact FAISS
\texttt{IndexFlatIP} (654\,MB) and a BM25 index (787\,MB) in the layout the
retrievers already load. Before any language-model run, a retrieval sanity
check confirmed genuine recall: the query \emph{``first-line treatment for
anaphylaxis''} returned a passage stating treatment ``with epinephrine
0.3--0.5\,mL'', and anatomy and pathology queries surfaced the relevant
textbook passages.

\section{Evaluation Harness}
\label{sec:impl-harness}

A profiler wraps every policy call and records latency (monotonic
nanosecond-resolution counter), peak memory (\texttt{tracemalloc}) and,
optionally, energy. Energy is estimated with \texttt{codecarbon}, imported
lazily so the test suite never pays for it, and reported in kWh with its
status as a software estimate stated plainly
(Section~\ref{sec:disc-limitations}). Measurement is strictly
\emph{sequential}: concurrent queries would corrupt process-level energy
readings, so no parallelism is permitted in the run loop, a constraint
imposed by the metric, not a limitation of the code.

Two scorers match the two question types. The multiple-choice scorer extracts
the predicted option letter through a cascade of patterns (leading letters,
``the answer is X'' phrasings, bare capitals); a scoring fix during analysis
made an explicit ``the answer is X'' statement take precedence over a
letter echoed from the choices, and re-scoring shifted results by only
0.5pp, confirming that the observed accuracy is a property of the answers,
not of the extractor. The open-ended scorer computes SQuAD-style token-level
$F_1$ against the gold paragraph. The $F_1$ routine lives in the scoring
module rather than the metrics module because the hallucination probe reuses
it to measure inter-draft agreement, a small early example of the design
anticipating the gate layer's needs. Binary correctness is deliberately not
reported for open-ended questions: thresholding $F_1$ at zero yields
$\sim$98\% ``accuracy'' and measures nothing; mean $F_1$ is the reported
metric.

\section{Demonstration Interface}
\label{sec:impl-demo}
% [DEMO] scripts/run_demo.py + src/medrag_adaptive/ui/ — screenshots in
% results/figures/demo/, captured 5 August 2026 on the 3B model.

A local browser interface runs one question through the gated policy and the
closed-book baseline and displays the gate's reasoning
(Figure~\ref{fig:demo-split}). It calls the same policy and gate factories as
the evaluation harness rather than reimplementing them, so what it shows is
the decision the harness would log, and it is scored by the same MCQ letter
extractor. Every gate member's signal, its firing rule and its vote are listed
individually, which makes visible what a single ensemble verdict hides:
members frequently disagree. Answers are only marked as agreeing when both
policies are \emph{correct}, since two identical wrong answers are the failure
this work studies, not a success.

\section{Reproducibility and Verification}
\label{sec:impl-verification}

The project treats reproducibility as a first-class deliverable, and this
section documents the machinery rather than asserting the virtue.

\paragraph{A model-free test suite.} 240 unit and integration tests pass at
the time of writing, executing without the multi-gigabyte model via the mock
backend's deterministic text and synthetic logit distributions (peaked and
uniform variants exercise both gate decisions).
Coverage spans configuration merge semantics, retrieval ranking and index
round-trips, loaders and risk tagging, every gate's threshold and abstain
behaviour, ensemble vote arithmetic and degraded-mode fallback, both P5
branches, scoring across answer formats, and the resumable run driver.
% VERIFY test count against `pytest --collect-only -q` before submission.

\paragraph{A single source of truth for numbers.} A canonical loader
re-scores raw logs in memory (raw logs are never mutated) and a generator
script emits both the results tables and a \texttt{numbers.tex} macro file;
every chapter cites macros such as \verb|\accPfiveMcq|, never literals. A
regression test fails the build if a reported number drifts from what the
logs produce, and the guard itself was verified to fail on a deliberately
planted literal (a test of the test). The handful of deliberately frozen
historical literals (pilot-corpus figures kept for contrast) are annotated as
such in the source.

\paragraph{Paired-run proofs.} The closed-book policy P3 never retrieves, so
its result is corpus-independent; a regression test proves the reference run
is a genuine paired run, with identical question IDs, identical order and zero
retrievals, which licenses reusing it across corpus conditions and saved a
3.2-hour re-run. Determinism was verified by replay: re-answering logged
questions at temperature 0 reproduced the logged answers exactly.

\paragraph{Resumability.} Long runs survive interruption by design
(append-only JSONL plus skip-on-resume), which is what made multi-hour
CPU-only experiments practical on a single laptop.
